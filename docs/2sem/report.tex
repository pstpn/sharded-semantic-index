	\reportheader{ВВЕДЕНИЕ}

	Рост объёмов данных в современных поисковых системах приводит к необходимости разбиения поискового индекса на части (шарды), размещаемые на разных узлах кластера.
	При обработке запроса необходимо определить, какие шарды могут содержать релевантные документы, и направить запрос только в них.
	Число опрашиваемых шардов (fanout) напрямую влияет на время отклика и нагрузку на систему.

	Актуальность исследования обусловлена тем, что классический подход к шардированию~--- хеш-разбиение терминов~--- распределяет термины случайно, не учитывая их семантические связи.
	Это приводит к высокому fanout, поскольку запрос, содержащий несколько связанных терминов, направляется в несколько разных шардов.
	Семантический шардинг, при котором совместно встречающиеся термины группируются в одном шарде, позволяет снизить fanout и, следовательно, уменьшить время обработки запроса.

	Цель работы~--- исследование производительности поисковых индексов, построенных на основе кластеризации поисковых запросов.

	Для достижения поставленной цели необходимо выполнить следующие задачи.
	\begin{enumerate}
		\item осуществить поиск существующих решений и подходов к шардированию в задаче построения поискового индекса;
		\item выполнить поиск набора данных поисковых запросов для кластеризации с целью шардирования индекса на основе полученных кластеров;
		\item реализовать прототип поискового индекса на основе полученных кластеров для найденного набора данных;
		\item исследовать производительность реализованного решения в сравнении с классическими способами построения индекса.
	\end{enumerate}

	\section{Анализ существующих решений}

	\subsection{Постановка задачи}

	Инвертированный индекс~--- основная структура данных в информационном поиске, отображающая термин в список документов, содержащих этот термин.
	При поиске по запросу система извлекает списки документов для всех терминов запроса, пересекает или объединяет их и ранжирует результаты (например, по BM25).

	При росте объёмов данных инвертированный индекс перестаёт помещаться на одном сервере и должен быть разбит на части~--- шарды.
	Возникает задача \textit{маршрутизации запроса}: определить, какие шарды могут содержать релевантные документы, и направить запрос только в них, минимизируя число опрашиваемых шардов при сохранении полноты поиска (recall).

	\subsection{Подходы к шардингу поискового индекса}

	Существует два основных подхода к шардированию инвертированного индекса~\srcmulti{1,2,3}.

	1. \textit{Шардирование по документам}.
	Каждый документ назначается в шард по $\mathrm{hash}(\mathrm{doc\_id}) \bmod N$.
	Это стандартный подход в Elasticsearch и большинстве распределённых поисковых систем.
	Документы распределены равномерно, однако каждый шард содержит все термины, и для обработки запроса необходимо опрашивать \textit{все} шарды (fanout~$= N$).

	2. \textit{Шардирование по терминам}.
	Каждый термин назначается в определённый шард, и шард содержит списки документов только для своих терминов.
	Документ назначается во все шарды, где есть его термины.
	Запрос маршрутизируется только в шарды, содержащие термины запроса.
	Fanout зависит от числа уникальных шардов терминов запроса.

	Однако оба подхода имеют свои недостатки, для решения которых предлагается такой подход, как семантический шардинг (по кластерам связанных терминов).
	Он отличается от шардирования по терминам тем, что назначение терминов в шарды производится не случайно, а на основе кластеризации, то есть совместно встречающиеся термины группируются в один шард.
	Это позволяет уменьшить fanout, поскольку связанные термины запроса с высокой вероятностью оказываются в одном шарде (особенно эффективно для часто встречающихся вместе терминов).

	\subsection{Обзор релевантных работ}

	Задача разбиения поискового индекса и маршрутизации запросов рассматривается в фундаментальной работе Маннинга и др., где описаны стратегии разбиения по документам и по терминам, а также методы оценки полноты маршрутизации~\srcref{4}.
	Ранний подход к определению релевантных коллекций для поиска представлен в системе GIOSS, где для каждого источника строилась статистическая модель на основе частотностей терминов, позволявшая оценить вероятность наличия релевантных документов без прямого обращения к коллекции~\srcref{5}.

	Метод Taily предлагает подход к выбору шардов на основе распределения оценок терминов в каждом шарде~\srcref{6}.
	Для каждого шарда строится приближение распределения оценок (tail распределение), и шарды ранжируются по вероятности содержать высокооценённые документы.
	В отличие от GIOSS, Taily не требует хранения глобальной статистики по всем терминам и лучше работает при большом числе шардов.

	Система BitFunnel реализует шардирование по терминам в промышленном поисковике Bing~\srcref{7}.
	Вместо традиционного инвертированного индекса BitFunnel использует битовую матрицу <<термин--шард>>, где каждый бит указывает наличие термина в шарде, что обеспечивает компактное представление и быструю маршрутизацию.
	Документы назначаются во все шарды, содержащие их термины, а запрос направляется только в шарды с совпадающими терминами.
	При масштабировании до миллиардов документов основной проблемой становится рост числа шардов и увеличение fanout.
	Система Maguro также реализует шардирование по терминам~\srcref{8}.

	В отличие от перечисленных подходов работы по эмбеддинговому поиску предлагают использовать векторные представления запросов и документов для маршрутизации~\srcref{9}.
	Однако такие подходы требуют значительных вычислительных ресурсов на обучение моделей и построение эмбеддингов.

	В текущей работе рассматривается промежуточный подход, который находится между статистическим и нейросетевым.
	Вместо обучения моделей для векторных представлений используется кластеризация на графе совстречаемости терминов, что позволяет группировать семантически связанные термины без обучения нейронной сети~\srcref{10}.

	\section{Реализация прототипа}

	\subsection{Построение индекса}

	Для построения индекса необходимо выполнить три основных этапа:
	\begin{enumerate}
		\item построить граф совстречаемости терминов с весами NPMI;
		\item кластеризовать граф алгоритмом Leiden с получением отображения \textit{термин~$\to$~шард};
		\item назначить каждый документ во все шарды, содержащие его термины.
	\end{enumerate}

	\subsection{Построение NPMI-графа совстречаемости}

	Для построения графа совстречаемости каждый документ представляется бинарным вектором терминов (факт встречаемости без учёта частоты) с фильтрацией стоп-слов и ограничениями на частотность.
	По матрице встречаемости вычисляется матрица совстречаемости (термины считаются совстретившимися, если они входят в один и тот же запрос), после чего для каждой пары терминов с достаточным числом совместных упоминаний рассчитывается нормированная взаимная информация (NPMI):
	\begin{equation}
		\mathrm{NPMI}(x,y) = \frac{\log\frac{P(x,y)}{P(x)P(y)}}{-\log P(x,y)}
	\end{equation}
	NPMI нормирует PMI к отрезку $[-1, 1]$, что удобно для сравнения ассоциаций разной частотности.
	Положительное значение NPMI указывает на то, что термины встречаются совместно чаще, чем при случайном распределении~\srcref{10}.
	Пары с отрицательным NPMI отбрасываются.
	В результате формируется взвешенный граф, где вершины~--- термины, рёбра~--- значимые совместные встречаемости, веса~--- значения NPMI.
	На наборе данных MS~MARCO v2.1 (train) граф содержит 15\,000 терминов (минимальное количество совстречаемости двух терминов для принятия~--- 2, минимальная частота появления в документах~--- 2, максимальная доля документов, содержащих термин~--- 0.5).

	\subsection{Кластеризация алгоритмом Leiden}

	Разбиение терминов на кластеры выполняется с помощью алгоритма Leiden на построенном NPMI-графе~\srcmulti{11,12}.

	\subsection{Назначение документов в шарды}

	Каждый документ назначается во все шарды, содержащие хотя бы один его термин.
	Это гарантирует полноту маршрутизации при поиске, но приводит к дублированию документов между шардами.
	Степень дублирования зависит от стратегии разбиения.
	При семантической кластеризации связанные термины оказываются в одном шарде, что приводит к меньшему дублированию по сравнению с хеш-разбиением.

	\section{Исследование производительности}

	\subsection{Методика исследования}

	Сравниваются две стратегии разбиения терминов по шардам:
	\begin{enumerate}
		\item \textit{Hash}~--- хеш-разбиение (по терминам);
		\item \textit{Leiden}~--- семантическая кластеризация.
	\end{enumerate}
	Обе стратегии назначают каждый документ во все шарды, содержащие его термины, и маршрутизируют запрос во все шарды, содержащие термины запроса.
	Набор данных MS~MARCO v2.1, раздел train (извлечено 120\,624 уникальных запроса и 129\,020 документов);
	В качестве метрик используются:
	\begin{enumerate}
		\item \textit{fanout}~--- число шардов, в которые направляется запрос;
		\item \textit{дублирование}~--- среднее число шардов, в которые попадает один документ;
		\item \textit{избыточность хранения}~--- отношение суммарного числа документов во всех шардах к числу уникальных документов.
	\end{enumerate}

	\subsection{Ограничения}

	Наряду с преимуществами выявлены следующие ограничения:
	\begin{enumerate}
		\item дублирование остается достаточно большим (15.1×). Дальнейшее снижение дублирования приведет к уменьшению полноты маршрутизации;
		\item результат кластеризации существенно зависит от токенизации и фильтрации стоп-слов;
		\item дрифт данных требует полного перестроения всех кластеров, а значит и индексов;
		\item параметры построения графа (пороги частотности) и кластеризации (разрешение) влияют на число и размер кластеров;
		\item построение индексов для большого набора данных (больше миллиона документов) может занять достаточно большое количество времени.
	\end{enumerate}

	\structheader{ЗАКЛЮЧЕНИЕ}

	По результатам проведённого исследования можно сделать следующие выводы:
	\begin{enumerate}
		\item выполнен анализ существующих подходов к шардированию поискового индекса;
		\item выбран набор данных MS~MARCO v2.1 (извлечена подвыборка из 120\,624 запросов и 129\,020 документов), обеспечивающий достаточный объём данных и публичную доступность для воспроизводимости исследования;
		\item реализован прототип семантического шардированного индекса на основе кластеризации запросов;
		\item проведены сравнительные исследования с хеш-шардированием (по терминам): средний fanout при Leiden-шардировании на 29\% ниже (2.3 против 3.2), дублирование документов на 38\% меньше (15.1× против 24.4×), routing recall при полном fanout составляет 100\% для обеих стратегий, при ограниченном fanout Leiden обеспечивает более высокий recall, чем Hash;
		\item выявлены ограничения: высокое дублирование (15.1×), увеличение числа шардов из-за хеш-назначения терминов вне графа, более высокая латентность шардированного поиска по сравнению с полным индексом при отсутствии распределения.
	\end{enumerate}

	Перспективными направлениями дальнейших исследований являются:
	\begin{enumerate}
		\item кластеризация с учетом содержимого документов;
		\item инкрементальное обновление кластеров при потоковом поступлении данных;
		\item селективное назначение документов в шарды с ограничением дублирования;
		\item оценка влияния кластеризации на итоговые метрики качества поиска (NDCG, MRR);
		\item оптимизация параметров (пороги частотности, разрешение Leiden) для различных сценариев использования.
	\end{enumerate}
