# Метод и протокол оценки

Документ описывает, что именно считает каждая стадия конвейера. Параметры — в
[справочнике параметров](configuration.md), формат результатов — в
[справочнике выходных файлов](outputs.md).

## Постановка

Индекс делится на шарды **по словам**: каждому слову назначается шард, документ хранится во
всех шардах своих слов, а запрос отправляется только в шарды своих слов. Чем чаще слова одного
запроса лежат в одном шарде, тем меньше шардов нужно опросить.

Сравниваются два способа назначить слову шард:

- **случайный** — по хешу слова;
- **семантический** — по кластерам графа, в котором связаны слова, встречающиеся в одних
  запросах.

Правило хранения одно для всех стратегий, отсюда два свойства:

- **полнота**: любой документ, содержащий слово запроса, лежит в шарде этого слова, поэтому
  опрос всех шардов запроса возвращает то же, что полный индекс;
- **дублирование**: документ хранится в стольких шардах, сколько разных шардов у его слов.

## Данные

**Корпус.** Из MS MARCO v2.1 читаются первые `dataset.max_rows` строк. Строка — запрос и около
десяти пассажей, найденных поисковой системой; асессор отметил те, что отвечают на запрос. От
каждой строки в корпус идут `dataset.docs_per_query` пассажей: сначала отмеченные, затем
остальные по порядку. Строки без отмеченных пассажей пропускаются. Одинаковые тексты
становятся одним документом: идентификатор документа — MD5 текста.

**Текст.** Запросы и документы приводятся к нижнему регистру, остаются последовательности букв
и цифр. Слово (терм) — такая последовательность длиной от двух символов, не входящая в
`text.stop_words`. Этот же разбор использует индекс Whoosh, поэтому слово, по которому
маршрутизируется запрос, заведомо проиндексировано.

**Разделение запросов.** Уникальные запросы идут в порядке набора данных. Первые
`queries.train_ratio` из них — обучающие: по ним строится граф. Остальные отложены и в
построении не участвуют.

## Граф слов

Вершины — слова обучающих запросов из букв (числа в граф не входят), встречающиеся не менее
чем в `graph.min_df` запросах и не более чем в доле `graph.max_df_ratio`, кроме стоп-слов и
слов из `graph.stop_words`.

Запросы с одинаковым набором слов графа считаются один раз. Пусть `N` — число таких уникальных
наборов, `n(a)` — число наборов со словом `a`, `n(a, b)` — число наборов с обоими словами.

Слова `a` и `b` соединяются ребром, если `n(a, b) ≥ graph.min_pair_count` и

```
NPMI(a, b) = ln( n(a,b)·N / (n(a)·n(b)) ) / ( −ln( n(a,b) / N ) )  ≥  graph.min_npmi
```

Вес ребра (`graph.edge_weight`) — NPMI, логарифм отношения правдоподобия Даннинга или χ² той же
таблицы сопряжённости. Набор рёбер от выбора веса не зависит.

## Кластеризация

Слова графа делятся на кластеры одним из алгоритмов `clustering.methods`: Leiden (модулярность),
Leiden с функцией качества CPM, Infomap, METIS. Каждый алгоритм проходит весь дальнейший
конвейер независимо от остальных.

## Стратегии

Кластеры покрывают только слова графа. Стратегия определяет, что делать с остальными словами
корпуса и как из кластеров получаются шарды.

**`base`.** Слово графа получает шард своего кластера. Слово вне графа получает шард по хешу в
отдельном диапазоне номеров `[n, 2n)`, где `n` — число номеров кластеров.

**`aff`.** Слово вне графа присоединяется к кластеру по документам. Каждый документ со словом
`t` голосует за кластеры своих слов графа, по голосу на слово. Пусть `v(t, c)` — число голосов
слова `t` за кластер `c`, а `m(c)` — число голосов за `c` по всему корпусу. При
`partition.affinity_vote: llr` слово идёт в кластер, в котором оно сильнее всего
перепредставлено: наибольшее G² Даннинга таблицы «голоса `t` за `c` против остальных», со
знаком минус при недопредставленности. При `raw` — в кластер с наибольшим `v(t, c)`. Слово, ни
разу не встретившееся в документе со словом графа, получает шард по хешу, как в `base`.

**`bal`.** Разбиение `aff` перестраивается под бюджет объёма: шард не должен содержать больше
`partition.balance.volume_cap` документов корпуса.

1. *Единицы.* Кластер в пределах бюджета — одна единица. Кластер крупнее бюджета дробится: его
   слова графа делятся на сообщества тем же алгоритмом, запущенным на рёбрах внутри кластера,
   а каждое слово вне графа присоединяется к сообществу по тому же голосованию (всегда `llr`).
   Если алгоритм оставляет кластер целым, его параметр удваивается, не более
   `max_refinements` раз. Единица, всё ещё превышающая бюджет, дробится снова, до глубины
   `max_depth`; единица без внутренних рёбер распадается на отдельные слова.
2. *Упаковка.* Единицы в порядке убывания объёма кладутся в тот шард, объём которого они
   увеличивают меньше всего (то есть с которым у них больше всего общих документов), если шард
   остаётся в пределах бюджета. Новый шард открывается, только когда ни один не подходит.

Слово, которое само встречается чаще бюджета, занимает отдельный шард. Число шардов — следствие
бюджета, а не числа кластеров.

**Реплики (`base_r<k>`, `aff_r<k>`).** Слово графа дополнительно кладётся в чужие кластеры, с
которыми связано сильнее всего. Сила связи слова с кластером — сумма весов его рёбер в слова
этого кластера. Слово получает до `k` шардов: свой и `k − 1` самых сильных чужих. Документы
дублируются вместе со словами, зато слова одного запроса чаще оказываются в общем шарде.

**`hash_<семейство>`.** Шард слова — остаток от деления MD5 слова на число шардов. Число шардов
берётся у стратегии `base`, `aff` или `bal` того же алгоритма, так что каждая стратегия
сравнивается со случайным разбиением на столько же шардов.

## Маршрутизация запроса

Покрытие запроса — упорядоченный список шардов, в котором у каждого слова запроса есть хотя бы
один его шард. Оно строится жадно: на каждом шаге выбирается шард, непокрытые слова которого в
сумме весят больше всего; при равенстве — шард с меньшим номером.

Вес слова (`routing.cover_weight`) — его IDF в BM25, `ln(N / (df + 1)) + 1`: первым опрашивается
шард самых редких слов запроса, которые сильнее всего влияют на ранжирование.

При бюджете `b` опрашиваются первые `b` шардов покрытия.

## Оценка

**Эталон.** Запрос выполняется в полном (нешардированном) индексе: BM25, логическое ИЛИ по
словам запроса. Сохраняются первые `evaluation.ranking_depth` документов.

**Выдача шардов.** Шард хранит документ целиком, поэтому частоты слов и длина документа в шарде
те же, что в полном индексе. Если шард считает BM25 по статистике всей коллекции (число
документов, документные частоты, средняя длина), оценка документа в шарде равна его оценке в
полном индексе. Поэтому выдача опрошенных шардов — это выдача полного индекса, из которой
оставлены документы этих шардов. Оценка так и считается, без построения индексов шардов;
точность этого расчёта проверяется отдельно (см. «Проверки»).

**Метрики запроса** при бюджете `b`:

- `overlap` — доля первых `evaluation.top_k` документов эталона, оказавшаяся в опрошенных
  шардах;
- `volume` — сумма размеров опрошенных шардов в долях корпуса: сколько документов пришлось
  просмотреть;
- `fanout` — число шардов в полном покрытии.

Разметка асессоров в метриках не участвует: измеряется то, что шардирование теряет
относительно полного индекса.

**Запросы без выдачи.** Запрос, ни одно слово которого не встречается в корпусе, ничего не
находит в полном индексе и не имеет шардов. Такие запросы исключаются из всех метрик.

**Выборки.**

| Выборка | Состав | Что показывает |
|---|---|---|
| `train` | случайная выборка обучающих запросов | верхняя граница: запросы, которые граф видел |
| `holdout` | отложенные запросы | основной результат: новые запросы того же источника |
| `ood` | случайная выборка запросов другого набора данных | перенос на другой источник |
| `connected_pairs`, `connected_triples` | пары слов графа с наибольшим весом ребра и тройки на их основе | слова, встречающиеся почти только вместе |
| `frequent_pairs`, `frequent_triples` | пары слов графа с наибольшим числом общих запросов и тройки | популярные сочетания частых слов |

Тройка — пара и их общий сосед, у которого слабейшая из двух связей с парой наибольшая.
Синтетические выборки зависят только от графа и одинаковы для всех алгоритмов.

**Доверительные интервалы.** Бутстреп по запросам: `evaluation.bootstrap.samples` повторных
выборок с возвращением, процентильный интервал среднего. Для сравнения двух конфигураций
интервал строится для средней разности на одних и тех же запросах.

**Срезы.** Отложенные запросы дополнительно делятся по связности своих слов в графе (средний
вес ребра по всем парам слов запроса; пара без ребра даёт 0) и по числу слов в запросе.

## Проверки

Стадия `verify` проверяет каждую стратегию каждого алгоритма. Стратегии по этим проверкам не
сравниваются: любое расхождение — ошибка, и конвейер останавливается.

**Полнота** — без выборки, по всем данным:

- раскладка документов по шардам пересчитывается независимо, по текстам документов, и
  сравнивается с сохранённой;
- для каждого запроса каждой выборки проверяется, что покрытие содержит шард каждого слова
  запроса.

Из этих двух условий следует, что полное покрытие возвращает каждый документ, который находит
полный индекс.

**Сверка с настоящими индексами.** Для `verification.queries` случайных запросов строятся
настоящие индексы Whoosh всех шардов из их покрытий, со всеми документами этих шардов. Запросы
выполняются в этих индексах с BM25 по статистике всей коллекции. Сравнивается:

- оценка каждого найденного документа в шарде с его оценкой в полном индексе;
- для каждого бюджета — расчётная выдача (эталон, отфильтрованный по документам шардов) с
  объединённой выдачей настоящих шардов.

Равенство не зависит от запроса и стратегии, поэтому достаточно нескольких запросов: каждый
даёт тысячи сравнений оценок.

## Устойчивость и абляции

Обе стадии меняют одну вещь, заново строят все стратегии от графа и измеряют их на отложенных
запросах теми же функциями, что основной конвейер; промежуточные файлы не сохраняются.

- **Устойчивость** (`sensitivity`) меняет условия, а не метод: зерно кластеризации, собственный
  параметр алгоритма и число обучающих запросов, по которым строится граф. Результат — ряды
  значений.
- **Абляции** (`ablations`) заменяют одно решение метода: правило голосования, порядок опроса,
  фильтр слов вопросной рамки, вес рёбер, пороги графа. Результат — именованные варианты рядом
  с основной конфигурацией.
