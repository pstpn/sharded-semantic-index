# Справочник параметров

Все настройки эксперимента находятся в одном файле — [`params.yaml`](../params.yaml).
В коде нет значений по умолчанию: каждый параметр задаётся в конфиге явно.

- **Проверка.** Конфиг проверяется при запуске любой стадии
  ([`sharded_index/config.py`](../sharded_index/config.py)). Неизвестный параметр, значение
  вне допустимых или ссылка на несуществующий алгоритм, стратегию или выборку останавливают
  запуск с понятным сообщением.
- **Пересчёт.** DVC следит за параметрами по разделам: после правки `dvc repro` пересчитывает
  только стадии, которые от неё зависят (столбец «Стадии» в таблице разделов).
- **Запись `null`** означает «не задано»; где она допустима, это указано.

## Разделы

| Раздел | Что настраивает | Стадии, которые пересчитываются |
|---|---|---|
| [`text`](#text) | стоп-слова | все, кроме `extract_pairs` |
| [`dataset`](#dataset) | исходный набор данных | `extract_pairs` и все следующие |
| [`queries`](#queries) | выборки запросов | `build_graph` (доля обучающих), `sample_queries` и все следующие |
| [`graph`](#graph) | граф совстречаемости слов | `build_graph` и все следующие |
| [`clustering`](#clustering) | алгоритмы кластеризации | стадии изменённого алгоритма, `report`, `describe`, `figures` |
| [`partition`](#partition) | стратегии разбиения | `build_partitions` и все следующие |
| [`routing`](#routing) | порядок опроса шардов | `evaluate`, `verify`, `sensitivity`, `ablations` и следующие |
| [`bm25`](#bm25) | ранжирование | `rank_queries` и все следующие |
| [`evaluation`](#evaluation) | метрики и интервалы | `evaluate` и следующие; только `report`, если менялись интервалы или сравнения |
| [`verification`](#verification) | проверки корректности | `verify`, `report` |
| [`sensitivity`](#sensitivity) | проверки устойчивости | `sensitivity`, `report` |
| [`ablations`](#ablations) | варианты «один рычаг» | `ablations`, `report` |
| [`describe`](#describe) | описательные таблицы | `describe` |
| [`figures`](#figures) | графики | `figures` |

## `text`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `text.stop_words` | список строк | любые слова в нижнем регистре | 151 слово | Слова, которые не индексируются, не маршрутизируются и не входят в граф. Стандартный английский список NLTK без `won` и `ma`. |

Слова `on`, `off`, `no`, `y` должны стоять в кавычках: без них YAML читает их как
логические значения, и конфиг не пройдёт проверку.

Идентификатор документа — хеш текста до удаления стоп-слов, поэтому смена списка не меняет
состав корпуса, но требует пересборки индекса.

## `dataset`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `dataset.name` | строка | имя набора на HuggingFace | `microsoft/ms_marco` | Источник запросов и пассажей. |
| `dataset.config` | строка или `null` | конфигурация набора | `v2.1` | Версия набора. |
| `dataset.split` | строка | сплит набора | `train` | Из какого сплита читаются строки. |
| `dataset.max_rows` | целое | > 0 | `200000` | Сколько первых строк набора читается. |
| `dataset.docs_per_query` | целое | > 0 | `2` | Сколько пассажей каждой строки идёт в корпус: сначала отмеченные асессором, затем остальные по порядку. Строка без отмеченных пассажей пропускается. |

## `queries`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `queries.train_ratio` | число | от 0 до 1, не включая границы | `0.95` | Доля уникальных запросов (по порядку набора), по которой строится граф. Остальные образуют выборку `holdout`. |
| `queries.sample_seed` | целое | любое | `42` | Зерно случайных выборок `train`, `holdout` и `ood`. |
| `queries.train_size` | целое или `null` | > 0; `null` — все запросы | `10000` | Размер случайной выборки из обучающих запросов. |
| `queries.holdout_size` | целое или `null` | > 0; `null` — все запросы | `null` | Размер выборки из отложенных запросов. |
| `queries.ood` | раздел или `null` | `null` — выборки `ood` нет | задан | Запросы из другого набора данных. |
| `queries.ood.size` | целое или `null` | > 0; `null` — все запросы | `10000` | Размер случайной выборки. |
| `queries.ood.dataset` | строка | имя набора на HuggingFace | `google-research-datasets/nq_open` | Источник запросов. |
| `queries.ood.config` | строка или `null` | конфигурация набора | `null` | Конфигурация источника. |
| `queries.ood.split` | строка | сплит набора | `train` | Сплит источника. |
| `queries.ood.column` | строка | имя столбца | `question` | Столбец с текстом запроса. |
| `queries.synthetic` | раздел или `null` | `null` — синтетических выборок нет | задан | Запросы, составленные из слов графа. |
| `queries.synthetic.size` | целое | > 0 | `2000` | Число запросов в каждой синтетической выборке. |
| `queries.synthetic.kinds` | список | `connected`, `frequent` | оба | `connected` — рёбра с наибольшим весом (слова, встречающиеся почти только вместе); `frequent` — рёбра с наибольшим числом общих запросов. |
| `queries.synthetic.arities` | список | `2`, `3` | оба | `2` — пары слов, `3` — тройки: пара и общий сосед с самой сильной слабейшей связью. |

Параметры задают набор выборок. Их имена используются в остальных разделах и в таблицах
результатов: `train`, `holdout`, `ood`, `connected_pairs`, `connected_triples`,
`frequent_pairs`, `frequent_triples`.

## `graph`

Граф строится по обучающим запросам. Запросы с одинаковым набором слов учитываются один раз.

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `graph.min_df` | целое | ≥ 1 | `2` | Слово входит в граф, если встречается не менее чем в стольких запросах. |
| `graph.max_df_ratio` | число | больше 0, не больше 1 | `0.5` | Слово не входит в граф, если встречается более чем в такой доле запросов. |
| `graph.min_pair_count` | целое | ≥ 1 | `2` | Два слова соединяются ребром, если встречаются вместе не менее чем в стольких запросах. |
| `graph.min_npmi` | число | от −1 до 1 | `0.0` | Ребро сохраняется, если NPMI пары не ниже порога. Порог применяется при любом `edge_weight`, поэтому состав рёбер от схемы весов не зависит. |
| `graph.edge_weight` | строка | `npmi`, `llr`, `chi2` | `npmi` | Вес ребра: NPMI, логарифм отношения правдоподобия Даннинга или χ². |
| `graph.stop_words` | список строк | любые слова | 29 слов | Слова вопросной рамки (`mean`, `definition`, `cost`…), исключаемые только из графа. Кандидаты и их признаки — в `metrics/frame_words.csv`. |

## `clustering`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `clustering.seed` | целое | любое | `42` | Зерно всех алгоритмов. |
| `clustering.methods` | словарь | имя → настройки алгоритма | 4 алгоритма | Каждый элемент порождает свою цепочку стадий (`cluster@имя`, `build_partitions@имя`, …). Имя используется в таблицах результатов и в путях файлов. |
| `clustering.methods.<name>.algorithm` | строка | `leiden`, `cpm`, `infomap`, `metis` | — | Алгоритм. |
| `clustering.methods.<name>.resolution` | число | > 0 | — | Обязателен для `leiden` и `cpm`, для остальных недопустим. |
| `clustering.methods.<name>.n_parts` | целое | ≥ 2 | — | Обязателен для `metis`, для остальных недопустим. |

| Алгоритм | Что делает | Свой параметр | Значение |
|---|---|---|---|
| `leiden` | Leiden, максимизация модулярности | `resolution`: чем больше, тем мельче кластеры | `1.0` |
| `cpm` | Leiden с функцией качества CPM (без предела разрешения) | `resolution`: порог плотности связей внутри кластера | `0.02` |
| `infomap` | Infomap, сжатие описания случайного блуждания | нет | — |
| `metis` | METIS: разрез на заданное число частей с минимальным весом разрезанных рёбер; части равны по числу слов | `n_parts`: число частей | `341` (столько кластеров даёт `leiden`) |

Чтобы добавить алгоритм или второй вариант того же алгоритма, достаточно новой строки:

```yaml
clustering:
  methods:
    leiden_fine: {algorithm: leiden, resolution: 5.0}
```

## `partition`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `partition.strategies` | список строк | имена стратегий, см. ниже | 10 стратегий | Стратегии, которые строятся и измеряются для каждого алгоритма. Порядок списка — порядок строк в таблицах. |
| `partition.affinity_vote` | строка | `llr`, `raw` | `llr` | Как слово вне графа выбирает кластер по документам, где оно встречается. `llr` — кластер, в котором слово значимо перепредставлено (G² Даннинга); `raw` — кластер с наибольшим числом голосов. |
| `partition.replica_affinity_quantile` | число или `null` | от 0 до 1; `null` — без порога | `null` | Реплики получают только связи «слово — чужой кластер» с суммарным весом не ниже этого квантиля. |
| `partition.balance.volume_cap` | число | больше 0, не больше 1 | `0.15` | Бюджет объёма шарда для стратегии `bal`: доля документов корпуса. Число шардов следует из бюджета. |
| `partition.balance.max_depth` | целое | ≥ 1 | `12` | Наибольшая глубина повторного дробления кластера, не уместившегося в бюджет. |
| `partition.balance.max_refinements` | целое | ≥ 1 | `5` | Сколько раз удваивается параметр алгоритма (`resolution` или число частей), пока кластер не разделится. У `infomap` параметра нет, попытка одна. |

Имена стратегий:

| Имя | Правило «слово → шард» |
|---|---|
| `base` | Слово графа лежит в шарде своего кластера. Слово вне графа получает шард по хешу в отдельном диапазоне номеров. |
| `aff` | Слово вне графа присоединяется к кластеру по голосованию документов (`affinity_vote`). Хеш остаётся только словам, которые ни разу не встретились в документе со словом графа. |
| `bal` | `aff` под бюджетом объёма: кластеры крупнее бюджета дробятся тем же алгоритмом, затем все части упаковываются в шарды до бюджета. |
| `base_r<k>`, `aff_r<k>` | То же, что `base` и `aff`, но слово графа дополнительно кладётся в кластеры, с которыми связано сильнее всего: всего до `k` шардов (`k` ≥ 2). У `bal` таких вариантов нет: шарды уже заполнены до бюджета. |
| `hash_base`, `hash_aff`, `hash_bal` | Случайное разбиение по хешу слова с тем же числом шардов, что у `base`, `aff` и `bal` соответственно. |

## `routing`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `routing.cover_weight` | строка | `idf`, `strength` | `idf` | Вес слова при построении покрытия запроса. Первым опрашивается шард, слова которого весят больше всего. `idf` — вес слова в BM25, `ln(N / (df + 1)) + 1`; `strength` — сумма весов рёбер слова в графе (0 для слов вне графа). |

## `bm25`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `bm25.k1` | число | > 0 | `1.2` | Насыщение частоты слова. |
| `bm25.b` | число | от 0 до 1 | `0.75` | Нормализация по длине документа. |

Параметры применяются и к полному индексу, и к шардам. Сохранённая эталонная выдача привязана
к ним: после изменения она пересчитывается.

## `evaluation`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `evaluation.top_k` | целое | > 0 | `10` | Глубина сравнения: доля первых `top_k` документов полного индекса, найденная в опрошенных шардах. |
| `evaluation.budgets` | список целых | возрастающие, ≥ 1 | `[1, 2, 3, 5]` | Сколько первых шардов покрытия опрашивается. Полное покрытие (`full`) измеряется всегда. |
| `evaluation.ranking_depth` | целое | ≥ `top_k` | `1000` | Глубина сохраняемой выдачи полного индекса. |
| `evaluation.bootstrap.samples` | целое | > 0 | `1000` | Число повторных выборок для доверительных интервалов. |
| `evaluation.bootstrap.seed` | целое | любое | `42` | Зерно повторных выборок. |
| `evaluation.bootstrap.confidence` | число | от 0 до 1, не включая границы | `0.95` | Уровень доверия интервалов. |
| `evaluation.comparisons.pairs` | список пар | имена из `partition.strategies` | 8 пар | Парные сравнения «стратегия минус база» внутри одного алгоритма, на одних и тех же запросах. |
| `evaluation.comparisons.reference_method` | строка или `null` | имя из `clustering.methods`; `null` — без сравнения алгоритмов | `leiden` | Алгоритм, с которым сравниваются остальные, стратегия со стратегией. |
| `evaluation.slices.sample` | строка | имя выборки | `holdout` | Выборка, для которой метрики считаются по частям: по связности слов запроса в графе и по числу слов в запросе. |
| `evaluation.slices.connectivity_quantiles` | целое | ≥ 2 | `4` | На сколько равных по числу запросов частей делятся запросы по связности (`Q1`…`Q4`). |
| `evaluation.slices.max_terms` | целое | ≥ 2 | `5` | Запросы с таким и большим числом слов объединяются в один срез (`5+`). |

Сравнение каждой стратегии с hash-разбиением её семейства (`base_r2` с `hash_base`, `bal` с
`hash_bal` и так далее) выполняется всегда и в `pairs` не указывается.

## `verification`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `verification.sample` | строка | имя выборки | `holdout` | Выборка, из которой берутся запросы для сверки с настоящими индексами. |
| `verification.queries` | целое | > 0 | `5` | Число случайных запросов на алгоритм. Для шардов из их покрытий строятся настоящие индексы. |
| `verification.seed` | целое | любое | `42` | Зерно выбора запросов. |
| `verification.score_tolerance` | число | > 0 | `1.0e-9` | Допустимое расхождение оценок BM25 между шардом и полным индексом. |
| `verification.workers` | целое или `null` | > 0; `null` — по числу ядер | `null` | Число процессов, строящих индексы шардов. |

Проверки полноты от этих параметров не зависят: они идут по всем документам и всем запросам
всех выборок.

## `sensitivity`

Каждая проверка меняет одну вещь, заново строит все стратегии и измеряет их на одной выборке.
Проверки выполняются для каждого алгоритма.

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `sensitivity.sample` | строка | имя выборки | `holdout` | Выборка для измерения. |
| `sensitivity.seeds` | список целых | любые | `[1, 2, 3]` | Дополнительные зёрна кластеризации (основное — `clustering.seed`). |
| `sensitivity.train_sizes` | список целых | меньше числа обучающих запросов | `[10000, 30000, 70000]` | Граф строится по первым N обучающим запросам. Корпус и измеряемые запросы не меняются. |
| `sensitivity.parameters` | словарь | имя алгоритма → параметр → значения | 4 алгоритма | Значения собственного параметра алгоритма: `resolution` для `leiden` и `cpm`, `n_parts` для `metis`. Строка нужна для каждого алгоритма из `clustering.methods`; у алгоритма без параметра (`infomap`) она пустая. Правка строки пересчитывает проверки только этого алгоритма. |

```yaml
sensitivity:
  parameters:
    leiden: {resolution: [2, 5, 10, 20, 50]}
    cpm: {resolution: [0.005, 0.01, 0.05, 0.1]}
    infomap: {}                                    # параметра нет
    metis: {n_parts: [361, 444, 569, 754, 1113]}   # столько кластеров даёт leiden на своих шагах
```

## `ablations`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `ablations.sample` | строка | имя выборки | `holdout` | Выборка для измерения. |
| `ablations.variants` | словарь | имя варианта → изменения конфига | 16 вариантов | Вариант перестраивается от графа для каждого алгоритма и каждой стратегии. |

Вариант записывается как фрагмент этого же конфига: раздел, параметр, новое значение.
Всё, что не указано, остаётся как в основной конфигурации. Менять можно разделы `graph`,
`clustering`, `partition` и `routing`: корпус, индекс и выборки у всех вариантов общие.

```yaml
ablations:
  variants:
    baseline: {}                                  # без изменений, строка для сравнения
    vote_raw: {partition: {affinity_vote: raw}}   # в разделе partition параметр affinity_vote = raw
    min_npmi_02: {graph: {min_npmi: 0.2}}
```

| Вариант | Что меняется относительно основной конфигурации |
|---|---|
| `baseline` | ничего |
| `vote_raw` | слово вне графа идёт в кластер с наибольшим числом голосов, без поправки на значимость |
| `cover_strength` | порядок опроса шардов задаёт сила слова в графе, а не IDF |
| `no_frame_stops` | граф строится без фильтра слов вопросной рамки |
| `edge_weight_llr`, `edge_weight_chi2` | вес ребра — LLR или χ² вместо NPMI |
| `min_npmi_01`, `min_npmi_02`, `min_npmi_03` | порог NPMI ребра 0,1, 0,2 и 0,3 вместо 0 |
| `min_pair_count_1`, `min_pair_count_3`, `min_pair_count_5` | ребру нужно 1, 3 или 5 общих запросов вместо 2 |
| `min_df_3`, `min_df_5` | слово входит в граф при 3 или 5 запросах вместо 2 |
| `max_df_001`, `max_df_0005` | из графа исключаются слова, встречающиеся более чем в 1% или 0,5% запросов |

Варианты меняют настройки, общие для всех алгоритмов, поэтому каждый вариант считается для
каждого алгоритма. Собственные параметры алгоритмов перебираются в `sensitivity.parameters`.
Если вариант должен изменить настройку одного алгоритма, он называет его по имени. Такой вариант
считается только для этого алгоритма:

```yaml
    cpm_fine: {clustering: {methods: {cpm: {resolution: 0.05}}}}
```

## `describe`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `describe.top_clusters` | целое | > 0 | `25` | Сколько крупнейших кластеров каждого алгоритма попадает в `metrics/clusters.csv`. |
| `describe.top_terms` | целое | > 0 | `10` | Сколько самых сильных слов кластера приводится. |
| `describe.frame_word_candidates` | целое | > 0 | `80` | Сколько самых частых слов запросов попадает в `metrics/frame_words.csv`. |

## `figures`

| Параметр | Тип | Допустимые значения | Значение | Описание |
|---|---|---|---|---|
| `figures.sample` | строка | имя выборки | `holdout` | Выборка, по которой строятся графики оценки. |
| `figures.top_clusters` | целое | > 0 | `25` | Число крупнейших кластеров на графиках структуры. |
| `figures.graph_max_nodes` | целое | > 0 | `1000` | Число вершин наибольшей степени на рисунке графа. |
| `figures.layout_seed` | целое | любое | `42` | Зерно укладки графа, t-SNE и облаков слов. |

## Переменные окружения

| Переменная | Назначение |
|---|---|
| `SSI_ROOT` | Каталог, относительно которого читаются и пишутся все артефакты. По умолчанию — корень репозитория. |
| `SSI_PARAMS` | Путь к файлу параметров. По умолчанию — `params.yaml` в `SSI_ROOT`. |

Обе переменные нужны для запуска стадий на других данных без изменения репозитория, например
для пробного прогона на малой выборке.
